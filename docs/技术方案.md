- 全新独立 Hyperf 项目，Docker 运行，宿主机无需 PHP 和 Composer。

# 5. 系统架构

```text
Codex ── POST /mcp ──> McpController ──> get_weather ─┐
                                                       ├─> WeatherService ─> WttrInClient ─> wttr.in
调用方 ─ GET /weather ─> WeatherController ───────────┘
```

设计约束：

1. Controller 和 MCP Tool 只处理协议与错误映射。
2. 所有业务查询统一走 `WeatherService::query()`。
3. `WttrInClient` 负责第三方请求和字段转换。
4. `WeatherResult` 统一 REST 与 MCP 的核心数据。
5. `/mcp` 直接返回 SDK 的 PSR-7 Response，不添加 REST JSON 信封。
6. 本机 PoC 使用单 Worker，保证握手时代 MCP 的内存 Session 在同一进程中可用；SDK 同时支持 2026-07-28 无状态协议。

# 7. RESTful 接口

```http
GET http://127.0.0.1:9601/weather?city=上海
```

`city` 去除首尾空格后必须为 1 到 100 个字符。

响应核心结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "location": {"city": "Shanghai", "country": "China"},
    "current": {
      "temperature": 21,
      "apparent_temperature": 19,
      "humidity": 44,
      "precipitation": 0,
      "wind_speed": 8,
      "weather_code": 113,
      "condition": "晴",
      "observed_at": "04:39 AM"
    },
    "units": {"temperature": "°C", "humidity": "%", "precipitation": "mm", "wind_speed": "km/h"},
    "timezone": "",
    "source": "wttr.in"
  }
}
```

| HTTP 状态 | 场景 |
|---:|---|
| 400 | `city` 缺失或格式错误 |
| 404 | 天气服务未找到城市 |
| 502 | 上游不可用、超时或返回无效 JSON |

# 8. MCP 接口

端点为 `http://127.0.0.1:9601/mcp`。路由支持 `POST`，并为 Streamable HTTP 生命周期保留 `GET`、`DELETE` 和 `OPTIONS`。

| 工具属性 | 值 |
|---|---|
| name | `get_weather` |
| 输入 | `city: string`，必填 |
| readOnlyHint | `true` |
| destructiveHint | `false` |
| openWorldHint | `true` |

成功时返回适合 Codex 阅读的中文 `content`，以及与 REST `data` 一致的 `structuredContent`。业务错误以 `isError: true` 返回，不泄露 PHP 堆栈或容器路径。
